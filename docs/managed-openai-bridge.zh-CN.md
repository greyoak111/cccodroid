# 本地 OpenAI 桥启动与卸载契约

本契约保留 streamfix 的 HMAC 通道，不读取额外的供应商密钥，不执行注册数据提供的命令。它只管理使用者显式配置的可选 `openai-bridge` 组件，不是通用本机代理探测器。源码合入即提供此路径；是否已经随某个 App / 组件版本发布，以各自的正式发行记录为准。

## v1 契约

组件由用户配置完成后，原子写入 `HOME/.cccodroid/services/openai-bridge.json`：

```json
{
  "schema": 1,
  "id": "openai-bridge",
  "endpoint": "http://127.0.0.1:34591",
  "runtimeDir": "/absolute/private/runtime",
  "instanceId": "00000000000000000000000000000000"
}
```

- `instanceId` 是安装实例的随机标识，**不是认证密钥**，不得代替本地连接认证。
- 文件不含上游 URL、认证信息、模型或任意命令；上游配置仍由组件自己的管理器处理。
- App 在 `startRun` 中、生成包装地址和启动 CLI 之前，匹配本轮原始 provider 端点。只有 `custom && !login && !local` 且精确的 `http://127.0.0.1:<1024..65535>` 根地址（允许末尾一个 `/`）可以匹配。
- 远端、其他端口、带用户信息/查询串/片段/额外路径/非规范主机写法不会启动组件。不存在或不可解析的注册不让其他接口承担桥的副作用。
- 匹配后必须确认本机组件安装记录 `state=ok` 且拥有固定入口，并检查真实路径，再由 Node 执行 `PREFIX/lib/openai-bridge/component.cjs ensure --dir <runtimeDir> --endpoint <endpoint> --instance <instanceId>`。不存在按注册文件执行任意命令的路径；启动校验失败不能因卸载的降级规则而放宽。
- 组件校验实例、端点和受管清单，启动其单例看护并等待实际健康就绪；成功时标准输出只返回 `{schema:1,id:"openai-bridge",ready:true,endpoint,instanceId}`，App 再次读取并核对注册/安装信息。失败使用非零退出码。
- App 等待上限 75 秒，失败结束本轮且显示错误，不向模型发送请求。同一实例并发等待共用一次启动操作；一次失败后 60 秒内不反复调用启动器。桥自身另有跨启动器调用有效的有限恢复预算。
- 成功就绪短缓存为 20 秒，不是健康保证：每轮仍核对注册、安装记录和固定入口，相关元数据或文件变化使旧成功结果失效。缓存期间服务意外退出仍依现有请求错误/重试链处理；缓存过期后重新 ensure，不靠重启循环绕过桥自身预算。
- 停止一个会话只取消该会话的等待，不杀其他会话共享的启动器/看护；本轮不再启动 CLI。生成阶段仍走现有请求取消链。

## 卸载不能依赖健康的启动契约

组件管理器先占住 `removing` 操作槽，拒绝新启动和重复组件操作；界面显示“正在卸载”，此阶段不能取消。已有短命 ensure 操作先取消，而不是等待其完整 75 秒超时后才开始卸载。正常卸载入口最多等待 40 秒。

卸载分两条路径：

1. **注册和安装记录有效：** 只调用固定组件入口 `uninstall --dir <runtimeDir> --endpoint <endpoint> --instance <instanceId> --yes`，不带 `--purge`。组件在停服或更改停用标记/注册前核对端点和实例，不能仅凭目录停止另一实例。成功停用并移除自身注册后，组件管理器才删除其受管包文件。合法入口失败时保留组件供排错/重试，返回卸载专用错误；网关记录失败阶段，不记录注册内容、子进程输出或密钥。
2. **注册缺失、损坏、字段不合法或 schema 无法识别，或安装记录/入口不健康：** 不根据这些数据执行脚本，也不从其中推测目录进行清理。清理固定的 `services/openai-bridge.json` 残留，并继续组件管理器原有的受管文件/记录清理。注册为符号链接时只处理链接自身，不跟随到目标。安装记录缺失或不能解析时，不猜测原文件归属，不递归删除私有运行目录或公共前缀；记录降级原因及未能确认的清理范围。

注册锁仅使用 util-linux 与 Android toybox 共同支持的 `flock -n`，由 JS 在一秒内有界重试，不依赖 toybox 不支持的 `-w`。工具不存在、不兼容或锁争用到期都不能被当成“未安装/无注册”：若已有注册却拿不到锁，卸载专用报错并保留包文件和记录，避免删包留注册的半截状态；没有注册则无需为了正常未配置组件创造锁依赖。测试前缀提供受控 flock，并明确覆盖缺工具及拒绝 `-w` 的实现，不能碰巧依赖开发机 node 同目录的 util-linux。

降级路径不承诺已停止无法验证身份的运行进程。它解决的是损坏元数据不能让组件永久卸不掉；正常受管实例仍走身份验证的安全停服。残留私有 Hook / 看护有独立的组件入口存在性检查，入口移除后不再重新拉起服务。默认不删除私有配置、密钥、日志、会话或历史，清除真实数据必须另获确认。

## 协议演进与发布顺序

本次明确限定一个组件和 schema 1，不把通用服务框架混入生命周期修复。未来可将受信安装记录中的服务声明推广为 `service: { entry, schema, commands }`，再由通用外壳管理；这需要单独评审入口归属、命令白名单、路径和多服务并发，不能直接信任注册文件声明的命令。

### v1 首次配套发布

1. **先合入/发布支持 v1 的 App。** 没有注册的旧组件和未配置用户不走此启动路径；旧 App 本身不能因组件更新自动获得 preflight。
2. **再发布带 v1 注册、ensure 和身份验证卸载的组件。** 市场由官方 CI 构建、签名；最终版本以维护者发行记录为准。两条 PR 可以协调合入，但不能把其中一方单独发布称为完整冷启动修复。
3. 用户完成显式配置/经确认的迁移后才发布服务注册。组件升级不自动覆盖旧私有运行副本或改写供应商列表；旧实例保留自己的停止/卸载管理器。
4. 最终签名配套版本必须完成原生新建、恢复、真实 APK 更新、有限恢复、并发、取消、其他接口和卸载八项验收。

### 从 schema 1 升级

- 同 schema 的不兼容字段/命令语义变化不可悄悄发布；未知字段在启动路径仍失败关闭。
- 先发布能同时识别旧 schema 与新 schema 的 App，并保留旧 schema 的启动和卸载回归，再发布默认写新 schema 的组件。组件仅在用户确认迁移后替换已有注册；不得为适配旧 App 把同一注册文件内容降格成错误实例。
- 旧 App 遇到未来 schema 时不得执行未识别的入口，卸载仍走固定注册残留清理和受管文件清理，不因未知版本卡住。不能将“卸载可降级”宣传为“旧 App 能自动启动新 schema”。
- 回滚组件/App之前保留私有配置并核对兼容矩阵；新 schema 的注册不能直接交给只懂旧 schema 的 App 自动启动。需要恢复时由用户明确确认，不能依赖重装覆盖或自动 purge。

## 图形配置与生命周期的接缝

用户在扩展页原有桥卡片的“卸载”旁进入“配置”。表单填写共用的 API 地址、API Key，再搜索或手填模型和该模型的上下文窗口；可添加多个模型、编辑/移除并选择一个默认项，沿用当前主题/字体。无需进入终端、找连接文件或手工复制第二把本地密钥；本地端口和随机连接认证由受管实现负责。

保存是独立的用户操作，不等于测试远端、切换当前会话或迁移旧手工桥：

- 浏览器提交 `endpoint`、可选 `apiKey`、默认 `model`、可选 `models:[{id,contextWindow}]` 和显式 `consent:true`；旧单模型请求仍接受 `contextWindow`。后端不接受任意运行目录、端口、组件入口或清除参数。组件保存用固定入口及 stdin JSON，不把远端密钥放命令行/日志。窗口留在宿主，传给组件的 `models` 仅是 ID 字符串数组。
- 只配置本组件的专用实例，不能覆盖已有不兼容私有副本或现用手工桥。修改会影响活请求时拒绝并提示稍后重试，组件操作与卸载/安装互斥。
- 旧 Key 不回显、不返回尾号；修改页留空表示保留，换服务来源必须重新输入。状态查询只返回非秘密配置与本地健康，不返回远端或本地连接密钥。
- App 创建/更新专用接口，但不改变全局默认或已有会话。只有用户点击“新建会话使用”才创建并选择该接口的新会话。
- 落盘、本地桥就绪和远端推理是三个状态。保存只进行本地工作，不发真实远端模型请求；远端测试若以后提供，必须另获确认并说明内容/费用。本轮成功页明确远端尚未测试。

### 本地故障与恢复预算

`configured=true` 只表示配置落盘，不等于可供新会话使用。组件状态与实际启动必须共同检查恢复故障、补丁校验和停用标记；残存服务 `/health` 成功不能覆盖恢复锁。组件通过固定 `localError` 返回原因，App 网关投影为 `local.state="error"` 和 `local.code`，前端在读取状态及保存后的提示都保留说明。

白名单为 `RECOVERY_EXHAUSTED`、`PATCH_VERIFICATION_FAILED`、`COMPONENT_DISABLED`、`LOCAL_START_FAILED`、`COMPONENT_UNAVAILABLE`、`UPDATE_REQUIRED`。未知错误不透传异常、路径、远端内容或密钥，按 `LOCAL_START_FAILED` 失败关闭。带阻断错误时，即使组件同时返回 `localReady=true`，网关和前端也不得启用“新建会话使用”。

恢复次数耗尽时明确提示：自动恢复已停止，修改配置不会解除；请先诊断，再明确重置恢复次数。打开配置、读取状态、保存、Hook 和普通 ensure 都不得清故障标记或用无限重试绕过预算。**本次没有实现图形“重置并启动”入口**，不把改配置重试宣传成恢复方案。

探活只记录时间及固定错误码，不记录请求头、响应正文或对话；日志须有权限、大小和保留界限。新诊断可以帮助后续区分失败，不能倒推此前未留证据的首次探活诱因。首次午夜探活失败的真实原因仍未确认，不能把恢复运行或修复状态展示写成已经修复全部历史根因。

### 可选自动模型清单

读取清单是与保存分开的远端操作：表单默认不连接远端；用户明确勾选允许后，API 地址和 Key 有效时约650毫秒防抖读取，可搜索选择，仍可手填模型。换服务来源撤销该许可，旧 Key 不能发往新来源。关闭页面、改地址/Key 或保存时取消旧请求并丢弃迟到结果，不缓存秘密或清单到浏览器存储、不自动选首项/保存/新建会话。

- 固定 POST `/api/components/openai-bridge/models`，仅接受 `endpoint`、可选 `apiKey` 和显式 `consent:true`；不要求先填模型。请求读取上限16 KiB，带了按次签名时核对请求体摘要。
- App 执行固定 `component.cjs gui-models`，stdin 仅传地址和 Key，不让请求选命令、目录或模型URL。App 自身不读上游旧 Key；组件仅在未输入新 Key 时，从完整且未变化的 GUI 管理实例读取同源 Key。
- 组件只将规范化 Chat Completions 地址末尾的 `/chat/completions` 替成 `/models`，保留来源和路径前缀。单次 HTTPS GET，正常验证证书，不代理、不重定向、不猜地址、不重试；12秒截止、远端1 MiB、最多500个唯一合法ID、返回128 KiB。
- 只返回模型 ID、可选的有效 `context_window`、截断标记及静态错误，不返回其他远端 body/元数据、认证头、异常或秘密。窗口必须是 1024–16777216 的整数，输出上限不能冒充输入窗口。401/403/404/429、空清单、不兼容格式、网络失败等均可手填回退，不阻塞保存。
- `fetching-models` 占组件操作槽，防止与安装/配置/卸载交错；不触发就绪缓存配置闸门、不停桥、不写配置或 provider。只读模型清单不等于推理测试；成功页需区分本地就绪、清单读取与模型推理状态，不能把曾主动连接清单说成完全未连接远端。

### 多模型和窗口

- 每个 API 最多配置 100 个唯一合法模型 ID，默认模型必须属于清单。组件 `gui-configure`/`gui-status` 的 `models` 是可选 ID 数组，旧单模型响应缺该字段时按 `[model]` 处理；保存多模型后必须核对组件回传的实际清单，不能把旧组件静默丢字段当作成功。
- 模型上下文按 ID 分别保存，新增项优先自动填写清单返回的有效窗口，缺失/非法时默认 200,000 token，允许手动修改。已保存值视为明确用户配置，重开、换 Key 或重新读取清单不会静默覆盖。模型切换不借用默认模型的容量；仅使用模型元数据，不用计费用量或输出上限推测窗口。
- App 写入纯本地的规范 `data:application/json;base64,…` 模型清单，并在固定非秘密映射中记清单哈希。归属验证仍拒绝任意远端/非规范/被修改或删除的 `modelsUrl`，连接实例指纹和固定入口检查不放宽。接口落盘前先记录精确旧/新指纹事务，最终映射写入失败后仍可冷读和重试；不是忽略哈希或接管任意已改接口。
- 显式内嵌的清单不按模型名字猜测能力并过滤；自动远端发现的通用过滤不变。清单使现有会话模型面板、冷缓存、模型 API 和 CLI 启动环境取到每个模型自己的窗口。保存不替换当前会话选择；用户在模型面板主动选择后从下一条消息起生效。
- 发布时需要配套组件保留此前 Android 执行层/生命周期修复。旧 App 对新增多模型不兼容，更新/回滚须核对配套版本，不能把只有前端更新宣传成支持多模型。

图形配置的代码、假数据回归和浏览器验收须与生命周期修正共同重测，静态设计稿不是实现通过证据。

## 测试与交付边界

`node scripts/test.mjs managed` 使用临时 HOME、假前缀、假组件和假注册，覆盖匹配、等待、并发、缓存、失败冷却、取消和卸载。图形配置真实入口为 `/api/components/openai-bridge/config`；表单、浏览器夹具和桥仓库的真实 App 路由联调必须核对这个实际路径，不能让两个自洽 mock 掩盖接口不一致。配置 POST 读取上限128 KiB（清单读取 POST 仍为16 KiB）；配置组件输出限128 KiB，以容纳多模型长 Unicode ID。带了按次签名时核对请求体摘要，不把无该签名的请求描述为必做摘要校验。

`node scripts/test-managed-ui.mjs` 是可选的无依赖 Chromium/CDP 合成验收，不由发版流程调用，不连接现用网关或真实模型。它放在 `scripts/`，会按上游现有 pr-guard 规则被列为“高”档并让 scan 标红，须维护者逐行审查；不能为拿绿色结果修改初筛规则、绕权限或声称已经获批。CDP evaluate/VM 调用执行的是本仓库表单/合成事件测试，保留供审查；测试使用独立 HOME/profile、限定自建 loopback origin、阻止外连，拒绝 chat 请求。词典和测试中的 `.invalid` / `.example` 地址为负面对照或保留域名，不向其发送真实请求。

这些是源码/合成浏览器验证，不是签名包或原生 App 验收。

只有配套组件实现本契约、实际归档安装测试及最终签名 App 真机验收完成后，才可承诺整套交付。用户对本地手工桥试用的退出重开反馈，不等同正式配套组件、真正冷态或 APK 升级验证；不会把旧可解码 URL 测试、预启动服务或先 502 再成功当成首请求前就绪证据。
