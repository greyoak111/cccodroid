# Bug 猎捕报告（2026-11-04）

本报告由 5 个并行代码审查子代理对全代码树（网关 `gateway/gw/`、`gateway/web/app/`、`android/assets/bin/` 及脚本，约 3.5 万行）逐行审查、再经人工复核与实测得出。所有发现均已对照当前 `main` 分支确认存在，行号以 2026-11-04 的 `main` 为准。

共确证 4 处缺陷，按严重程度排序：

---

## 1. 🔴 权限模式切换的运算符反转（安全相关）

**位置**：`gateway/web/app/03-perm-status.js:444`

```js
if (!mode || (mode === state.permissionMode && mode === "bypassPermissions")) return;
```

**问题**：条件里的 `===` 应为 `!==`。紧跟其上的注释写明了设计意图（安全通告 GHSA-2w6p 的修复）：

> 不能只看标签一样就不发：标签可能是旧的（重放过旧事件），用户要收紧时必须真送到网关

即：所选模式与当前相同 **且不是** `bypassPermissions` 时才跳过发送；对 `bypassPermissions` 要每次都真发（并弹确认）。现在的写法恰好相反：

1. 前端标签（可能因重放旧事件而过期）显示已是「全部放行」时，用户再点一次「全部放行」会被这里静默 `return`——确认对话框不弹、请求不发，用户以为已重申，实际什么也没发生；
2. 反过来，普通模式下重复选择当前模式每次都会无谓地重发请求并弹 toast。

**修复方向**：`mode === "bypassPermissions"` 改回 `mode !== "bypassPermissions"`。

## 2. 🔴 自检工具连错网关端口

**位置**：`android/assets/bin/cccodroid-selftest:141`

```sh
GP=${CCAPP_PORT:-8791}; case "$GP" in ''|*[!0-9]*) GP=8791;; esac
```

**问题**：网关真实默认端口是 **8790**（`gateway/gw/config.mjs:23`：`port: Number(process.argv[2] || process.env.CCAPP_PORT || 8790)`），这里默认与兜底两处都被写成了 8791。`CCAPP_PORT` 未设置时，自检的「状态对账」一节必然连不上网关（或撞上 127.0.0.1 上被其他应用占住的端口），对账永远 FAIL。

**修复方向**：两处 `8791` 改为 `8790`。

## 3. 🟡 frontmatter 正则丢失反斜杠

**位置**：`gateway/gw/settings.mjs:29-30`

```js
name = (fm[1].match(/^name:s*(.+)$/m) || [, name])[1].trim();
desc = (fm[1].match(/^description:s*(.+)$/m) || [, ""])[1].trim();
```

**问题**：正则里的 `s*` 应为 `\s*`（空白）。字面 `s*` 表示「零或多个字母 s」。常规写法（`name: xxx`，冒号后有空格）碰巧不炸，但冒号后无空格且值以字母 s 开头时会吃掉首字符。实测：

```
"name:styles".match(/^name:s*(.+)$/m)[1]  // → "tyles"（错误）
"name:styles".match(/^name:\s*(.+)$/m)[1] // → "styles"（正确）
```

**修复方向**：两处 `s*` 改为 `\s*`。

## 4. 🟡 GLM 套餐额度窗口单位疑似对调（待对照确认）

**位置**：`gateway/gw/providers.mjs:563`

```js
window: x.unit === 3 ? "5h" : x.unit === 6 ? "week" : x.unit === 5 ? "month" : String(x.unit || ""),
```

**问题**：unit 编号 3、5、6 对应的时长应单调递增（5 小时 < 周 < 月），即 `3 → 5h、5 → week、6 → month`；这里 6 映射成 `"week"`、5 映射成 `"month"`，顺序颠倒。后果：设置页显示智谱 Coding Plan 额度时，「每周额度」标成「每月」、「每月」标成「每周」。

**注意**：此条审查时离线，无法对照真实 z.ai API 响应做最终确认，置信度中等。建议对照一次真实 `/api/monitor/usage/quota/limit` 响应后再改。

**修复方向**（确认后）：交换 unit 5/6 的映射。
