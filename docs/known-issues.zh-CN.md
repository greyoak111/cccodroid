# 已知问题与未排除的隐患

[English](known-issues.md)

这里列出**还没查清根因、也没能完全排除**的问题。日常使用中基本碰不到，但我们不想把它们藏起来。碰到了请在 App 里点 **设置 → 排障 → 到 GitHub 反馈**（机型、系统版本、自检结果会自动填好），写上当时在做什么；需要日志时再附「我卡住了 · 打包诊断」生成的 zip。和机型、厂商系统有关的问题见下面第 6 节。

## 1. ~~输入法打不进输入框（移动端神秘 bug）~~ 已在 0.3.7 修复

- **现象**：刚打开 App 时点输入框，键盘弹出、输入法有候选，选的字却上不了屏；英文能打，分屏或切屏后就好了。
- **原因**（2026-10-21 用输入法事件流记录查清）：页面一加载完，新会话就用脚本把焦点放进输入框。那时键盘没起来，WebView 没有为它建立输入连接，输入法手里还是页面刚出来时的空连接。之后再点输入框，焦点没变，WebView 只叫出键盘、不换连接，选的字都交给了空连接。分屏、切屏会让窗口失焦再得焦，连接重建，所以能好。
- **修法**：手指抬起后检查一下，焦点在可编辑处、输入法却还拿着空连接，就让输入法重新连接一次。
- 还碰到的话，请照文首的方式反馈。

## 2. 触摸滚动整个冻住（已有补丁，根因在 WebView，未修）

- **现象**：对话区、侧栏、各种面板，所有地方都划不动了；按钮能点，也能打字。不会自己好。
- **什么时候出现**：开发端真手指正常使用时反复出现过，不是测试造成的。发行版用的是同一个系统 WebView，也会碰到。
- **查到的**：
  - 冻住时手指的触摸事件照常送到了页面，页面没有拦（没有 `preventDefault`，也没有设 `touch-action`），就是不出滚动。用脚本改滚动位置、用鼠标滚轮都能滚。
  - 重新加载页面不好，切到后台再回来也不好；**让 WebView 跳到另一个站点再跳回来，马上就好**。
  - 所以卡住的是 WebView 内部给这个页面的那份手势状态，不在我们的页面代码里。我们的某个操作会不会正好踩中它，还不知道。
- **0.2.0 起的补丁**：
  - **自动**：连续两次「手指竖着划了一段，那块区域明明还能往那个方向滚，却一动不动」，App 就自动把界面跳出去再跳回来，大约一秒。正在进行的回复在网关那边照常跑，输入框里没发的字会填回去。一分钟内最多自动做一次。
  - **手动**：长按顶栏的标题（会话名那里）一秒左右，做同样的事。自动没反应时用它。（0.3.18 及以前是顶栏的雪花按钮 ❄。）
  - 这只是绕过去，不是修好。
- **诊断**：每次脱困都会在页面存储里（`localStorage` 的 `cc.freezeLog`）记下当时最近的触摸记录，只留最近 5 次。目前只有开发版能读到。
- **以前的做法**（0.1.19 ～ 0.2.0-rc1）：检测到拖不动时由脚本接管滚动。实测它帮不上忙，有时还让情况更糟，已去掉。

## 3. 折叠屏（实验）

0.4.18 起排版跟着折痕走（见 [large-screen.md](large-screen.md) 的 "Foldables"）。目前只在 Android 模拟器上验过，真机可能有出入，欢迎到 [#19](https://github.com/greyoak111/cccodroid/issues/19) 反馈。不想要可以在 设置 → 外观 里关掉。

## 4. 非桌面方式启动时一闪而过的灰色蒙层

用 adb、通知等方式（不经桌面图标）冷启动时，安卓 12+ 会先画一层系统启动画面。0.2.0-rc1 起这层已改成与安装页同色、不放图标；但在红魔 9 Pro 上开窗瞬间仍有约半秒的半透明灰色蒙层压在页面上，推测是 ROM 自己的开窗动画，未证实。从桌面图标点开不会出现。

## 5. 顶栏偶尔显示「界面脚本出错：Script error.」（调查中）

- **现象**：顶栏副标题变成「界面脚本出错：Script error.」，后面没有文件名，也没有原因。界面一般还能照常用。
- **为什么只有这一句**：外壳（安卓那一层）会往页面里调几段代码，比如返回键、保存文件后的回调、系统深浅色切换、通知点进会话、分享内容进来。这些代码里冒出来的错，WebView 出于安全考虑会把细节抹掉，只剩这一句。所以单看它，查不出是哪一处出的错。
- **查到的**（2026-10-22）：在测试壳里把这些入口逐个打了一遍，0.3.13 里都不再出这句。只抓到一个真问题：从别的应用分享文字进来时，文字插进去了，同时报「t is not a function」，已修。用户截图里那次多半来自前几天改版期间、已经修掉的回归，但没法回放确认。
- **0.3.13 起**：外壳调页面的每段代码都自己接住错误，顶栏会写成「界面脚本出错：入口名：原因」，比如「__ccBack：……」。还碰到的话，截图里有入口名就能直接定位，请照文首的方式反馈。

## 6. 各家系统与芯片（实测只有两台）

亲手测过的只有两台：**联想 TB320FC**（ZUXOS，Android 15，骁龙 8+ Gen 1）和**红魔 NX769J**（中兴系系统，Android 14，骁龙）。下面其他品牌的设置路径来自公开资料和常见做法，**没有亲手验证**，菜单名可能因系统版本不同。更详细的各家步骤可以看 [dontkillmyapp.com](https://dontkillmyapp.com)。

你的机型碰到问题，请到 **设置 → 排障 → 到 GitHub 反馈**：机型、系统版本、自检结果会自动填好，你只要写遇到了什么。没有 GitHub 账号就用旁边的「打包诊断」。

用起来没问题也欢迎报一下：到 GitHub 新建 Issue，选「[机型报告](https://github.com/greyoak111/cccodroid/issues/new?template=device.yml)」，或者在 QQ 交流群 1062538743 里说一声。实测过的机型越多，这一节就越可靠。

### 所有机型都一样的

- **系统版本**：能装的最低版本是 Android 8.0，实测跑过 14、15 和 16。
- **后台**：App 一直挂着一个前台服务（通知栏那条），原生安卓的后台限制挡得住；**挡不住的是厂商自己的冻结和清理**。被冻结时网关和正在跑的任务会整个停住，回到前台才接着跑。App 检测到被冻结过，会在设置里提示，并给出你这个品牌的设置路径。
- **GPU 组件大多只支持骁龙**：骁龙 GPU 驱动（两个）、GPU 跑分、clvk 都依赖高通 Adreno 的 `/dev/kgsl-3d0`。0.3.3 起，Mali GPU 的机器（联发科天玑等）可以装 `gpu-driver-mali`，直接用厂商自带的 Vulkan 驱动，已在 Redmi K70 Ultra 和 vivo V2502A 上实测通过（[#14](https://github.com/greyoak111/cccodroid/issues/14)）。三星 Exynos、华为麒麟的机器上，扩展页会标「只限骁龙」，装不了。Blender、llama.cpp 这类能用 GPU 的组件在没有对应驱动的机器上照样能装，会退回 CPU 跑，慢一些。有这类机器的人反馈越多，越好推进。

### 联想（ZUI / ZUXOS）· 实测

主力开发机，所有功能都在这台上测过。没见过厂商冻结。

### 红魔 / 努比亚 / 中兴 · 实测

- **后台约 90 秒就会冻结整个应用**，前台服务和电池白名单都挡不住。要到 应用信息 → 应用的电池用量 → 电池优化 → **后台运行：允许**。
- 同一页的**自启动**也选允许。设成「自动」时，更新后自动恢复、开机激活 Shizuku 都会被系统拦掉。
- Android 12 起，系统设置页会把第三方悬浮窗藏起来，所以 Shizuku 无线配对码放在通知里输入。
- 不从桌面图标冷启动时，偶尔有半秒灰色蒙层，见第 4 条。

### 小米 / 红米（HyperOS / MIUI）· 未实测

清后台比较激进。应用信息 → **省电策略：无限制**，**自启动**打开；在多任务界面把 cccodroid 的卡片锁住，免得一键清理把它杀掉。

### OPPO / 一加 / 真我（ColorOS / OxygenOS / realme UI）· 实测

一加 Ace 5（ColorOS 16，Android 16）上，首装下工具包、对话、终端、可选组件、分屏横屏都正常（[#61](https://github.com/greyoak111/cccodroid/issues/61)）。

一加 Ace 7 Pro（PMS110，OPlus ROM 17，Android 17）上，对话、终端、Shizuku、设备工具、短时后台都正常，可选组件 23 个里 20 个能用（2026-11-04 群友适配报告）。没用上的两个是 `gpu-driver-glibc` 和 `clvk-glibc`：glibc 侧的 Turnip 还不认识 Adreno 840；bionic 侧的 `gpu-driver` 正常。长时间挂后台、分屏横屏还没测。

- **后台迟早会被杀**，这是 ColorOS 的调度决定的，前台服务挡不住。Ace 5 的报告者是靠第三方保活模块才留住的。
- 能做的先做上：应用信息 → 耗电管理 → **允许后台行为**、**允许自启动**；多任务卡片锁住。

### vivo / iQOO（OriginOS / Funtouch OS）· 未实测

设置 → 电池 → 后台耗电管理 → cccodroid **允许后台高耗电**；i管家里允许**自启动**。

### 华为 / 荣耀（HarmonyOS / MagicOS）· 未实测

设置 → 应用启动管理 → cccodroid 关掉「自动管理」，手动允许**自启动**、**关联启动**和**后台活动**。HarmonyOS NEXT（纯血鸿蒙）不能装安卓应用，用不了。

### 三星（One UI）· 未实测

应用信息 → 电池 → **不受限制**；设置 → 电池 → 后台使用限制里，把 cccodroid 加进「永不休眠的应用」。国行和美版多是骁龙，其他地区不少是 Exynos，Exynos 机型用不了 GPU 组件。

### 谷歌 Pixel 与类原生系统 · 未实测

后台按原生安卓的规矩来，前台服务够用。Tensor G1–G4 是 Mali GPU，理论上能用 `gpu-driver-mali`，还没人实测过；其他 GPU 组件用不了。

## 7. 有的第三方调用看不到附图，模型照着乱编

附图平常是这样进去的：消息末尾带一个 `@路径`，Claude Code 用 Read 工具把图读回来，图落在「工具结果」里。官方接口和各家厂商的官方接口都认这个位置。

有的第三方调用方式把 Anthropic 协议转成 OpenAI 协议时，不处理工具结果里的图：要么整张丢掉（模型说「没收到图像」），要么把图片编码当成一大段文字塞给模型，模型读着乱码，编出一张毫不相干的图，而且说得很肯定。群友排查时有个好办法：看这一轮的输入 token 数。正常看一张图大约几百到一千出头；只有两百左右说明图丢了；涨到上万说明图被当成了文字。

**处理：** 0.5.8 起，自定义接口卡上有一项「图片随消息一起发（兼容）」。勾上后，附图会另带一份直接放进用户消息（各种调用方式都认这个位置）；`@路径` 那条路照旧，两条并存。太大的图先缩到长边 1568 再发；插话里的大图不缩，仍只走 Read。Anthropic 官方和各家厂商自己的接口用不着勾。

## 8. 打开后一直停在「等待网关…」（调查中）

一位群友在三星平板（One UI，安卓 16）上碰到过：打开应用后，启动页停在「等待网关…」两三分钟才进界面。排障日志里网关每次都正常启动了，没有报错；当时手机正好断网，根因还没查清。

另一种已查清的情况：0.6.8 在有的手机上（应用目录路径经过系统链接，比如荣耀 MagicOS、安卓 17）网关起一次退一次，通知里是「网关已退出，8 秒后重启」，一直循环。0.6.9 已修。

**处理：** 先升到最新版。卡在这里时多等一两分钟，别反复划掉重开——每重开一次都会从头再等。等过了还进不去，进去以后到 设置 → 排障 点「打包诊断」发给我们。

## 9. 会话区偶尔整片空白、怎么划都不动（调查中）

一位群友在小米手机（HyperOS，安卓 16）上碰到过：冷启动后打开一个较长的会话，顶栏和输入框都在，消息区却是一片空白，连划十几下都没反应，只能划掉应用重开。排障日志里网关一直正常，界面没有报错，也没有触发自动脱困（每次划的距离都很短）。触发条件还没找到，可能和第 2 条是同一类 WebView 问题。

**处理：** 碰到时先长按顶栏标题约 0.6 秒（脱困），或者切到别的会话再切回来。如果都不行，重开以后到 设置 → 排障 点「打包诊断」发给我们，并说一下出问题前在做什么（刚打开应用、刚打开这个会话，还是从后台切回来）。

## 10. 应用内更新报「出错 · 读不到签名」（未修）

一位群友的手机每次应用内更新都停在这一步。更新前要先核对下载的安装包是不是同一把发布钥匙签的；这一步用系统接口读安装包的签名，他那台手机的系统接口什么也没返回，于是拒装。安装包本身没问题（逐个核过，签名和以前各版一致），是这台手机的系统接口读不出来。

**处理：** 到 GitHub Release 或官网下载安装包，直接覆盖安装，数据不受影响。

## 给开发者：测试动作本身会制造假问题

上面第 1 条和自动化测试有关（第 2 条已确认不是），修这类问题之前请先确认**不跑测试时也会出现**：

- `input swipe` / `input tap` 注入的事件会被一些 ROM 的系统手势监听取消，有时还会多出一下点击。
- 截屏、开模拟副屏、启动别的窗口、用 `ime set` 切输入法，都可能把输入焦点或输入法连接从 App 那里拿走。
- 拖动、滑动、输入法这类问题，以真手指、真输入法的结果为准。
- 全量测试（`node scripts/test.mjs`）在机器满负载时，`merge.test.mjs` 的「记录与兜底」偶尔失败一次，单独跑稳定通过，是时序问题，还没修。全量里只有它挂时先单独重跑确认。
