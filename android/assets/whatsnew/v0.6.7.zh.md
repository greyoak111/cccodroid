这一版主要做安全：Claude Code 和网关跑的程序都要先核过，Claude Code 的配置也要先查过才交给它。另外合并了一批群友的修复。

## 安全

- Claude Code 要对得上 Anthropic 签名的清单才运行。新装的版本会自动存好清单；早先装的、没有清单的版本，会先联网补上，补上之前不运行。
- 网关加载自己的代码时逐个文件核字节，核完再换文件不管用。
- 网关单独用一份自己的运行库（Node、它要的库、启动 Claude Code 用的 glibc），放在工具包外面，每次启动前按安装包核一遍，pkg 升级和工具包更新都碰不到它。第一次启动会从工具包里拷一份过去，**多占约 105 MB**；工具包里的版本对不上时会联网下载（约 130 MB）。
- 应用自己的小程序挪进了安装包里；网关和 Claude Code 不让别的进程调试或读写内存。
- Claude Code 的配置（CLAUDE.md、规则、技能、命令、子代理、输出风格、插件、MCP、自动记忆）先过一遍破甲特征检查，再由网关交给 Claude Code；命中的那一轮不运行，并告诉你是哪个文件哪一行。终端里的 claude 走同一套。插件里的 hooks 不运行；技能要用 `/user:名字` 调用。
- 往 CLAUDE.md、`.claude/` 和记忆目录里写破甲内容，会被安全检查拦下。
- 用量查询只认精确的主机名。
- 详细说明见 SECURITY.md 的「网关和 Claude Code 跑的代码」一节。

## 改进

- 这一轮答完、只剩后台任务在跑时，`/compact`、`/context` 这类命令直接发进去执行，不用再等后台任务全部结束。还在生成时照旧排队。

## 修复

- 保存文件时先解析路径再核目标，`/.` 这类写法绕不过去，也不会写到非普通文件上。
- Git 项目的信任记录把钩子内容、完整配置和 gitdir 都算进去，改了要重新确认。
- 组件读用户能改的文件之前先确认是普通文件。
- 账本里有坏掉的记录不会再让网关崩掉。
- 分段下载写盘时一直写满为止，不再有写了一半却当成功的情况。
- 上游连接被重置时，补尾能送到界面。
- 并发会话缩图时临时文件不再撞名。
- 定时任务「跳过下一次」只跳过对应的那一次。
- 配置变了以后，⚡ 立即发送会结束空闲的那一轮，不再一直卡着。
- 分叉出来的会话时间相同时，按创建时间排先后。
- 启动时读不到的应用文件也会还原。
- 开着一轮时另开对话，不再卡在用户配置确认上。
- 停掉任务后，没做完的清单也能点 ✕ 收起。
- 配置里在提醒「别照做」时引用了越权句子（比如 claude.ai 同步来的官方技能 import-memory），不再被破甲检查误拦。
- 命令输出里的图片路径在本机读不到时（比如 SSH 连着的服务器上的），提示可能在远程机器上，不再只说「读不到」。
- 之前的对话留下的后台程序点了「保留」以后，它新起的子进程不再弹确认，网关重启后也还记得（#167）。
- 「保存到」、静默安装失败、更新循环、「回退并重新提问」等几处卡住或白等的问题。
