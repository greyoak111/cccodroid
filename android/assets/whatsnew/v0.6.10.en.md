This release fixes everything in chenshi723's full audit of 0.6.9 (#180–#200) plus a privately reported security issue, and adds two more rounds of jailbreak-check hardening — over a hundred fixes in all.

## Security

- "Is this the app's private directory?" is now decided by the directory's identity, so alternate spellings, symlinks and parent directories no longer get around it; projects, the file panel, Git, previews and Office all go through the same check.
- Release-edition lockdown tightened: `@` imports in project instructions can't leave the project root; hooks in skill / subagent front matter are stripped from the copies; a project's output style can't replace the built-in or your own styles; MCP servers and permission rules carried in by the release edition need your confirmation on a card.
- Git only trusts registered project directories; the guard deploys only verified source; writing shell startup files or `~/.cccodroid/bin` now asks first.
- The jailbreak check recognizes more disguised forms (look-alike letters, separators between words, layered wrappers, direct phrasing in several languages) and a whole family of payload phrases from the red team; everyday wording still passes.
- Android side: the internal action key is derived from the system keystore instead of stored in plain text; the system file picker can't hand back the app's own internal files; Docs file access no longer exposes Claude Code's settings files; the UI verifies the gateway on every request, so input is never sent to another app squatting on the port.
- Components and toolkit: the component index can't be rolled back and its cache is re-verified by signature; `devkit.lock.json` is signature-checked; uninstall only deletes paths inside the prefix; skill packages have an entry limit.

## Fixes

- Run pipeline: stopping the gateway takes the running Claude with it; a permission prompt nobody answers for 30 minutes counts as denied; one bad event no longer brings the gateway down; a run still finishes on time when Claude has exited but something holds its pipes.
- Interruption and recovery: the interrupted card tells apart an app update, the gateway being closed or restarted, and the system killing it; recovered runs no longer report "history was edited"; a run stopped before it started offers "resend" instead of "continue".
- Provider settings: a broken file is kept aside instead of overwritten; changing the host clears the old key; switching providers clears the old auto-title model; malformed fields are ignored.
- Scheduled tasks: a run the system delayed by up to 30 minutes still runs instead of counting as missed; the background service exits after the run; if it can't start in the background you get a notification to open the app.
- Toolkit upgrades no longer delete your own files under `$PREFIX`; a component upgrade that fails halfway rolls back to the old version.
- State files, project instructions and the ledger are written atomically and kept aside when unreadable; plus batches of fixes to session delete / search / import / export, bookmarks, the Git panel, file and Office previews, and the terminal.
- When the upstream API returns an error, the message now adds what to do about it (context too long, wrong key, out of credit, rate-limited, server error, …).
- Files shared in from other apps are only saved after you confirm; removing one from the attachment bar deletes the copy.
- Opening the gateway address in a phone browser now says "Open this in the cccodroid app" instead of "gateway offline", and the browser tab shows the app icon.

## Behavior changes

- Git only trusts registered project directories; outside the workspace, unregistered directories no longer pull `CLAUDE.md` from parent folders; `@` imports in project instructions can't leave the project root.
- The "don't ask again" window for privileged commands is selectable, up to one week.
- In the release edition, changed MCP or permission rules take effect only after you confirm them on a card; scheduled tasks wait while such changes are unconfirmed.
- Switching the global provider clears the old provider's model name from projects and scheduled tasks that follow the global setting.
- If the chosen working directory no longer exists, the run fails with an error instead of quietly running in the workspace.
- The interrupted card goes away only after the "continue" run actually answers.
- Picking the app's own internal files in the system file picker is ignored; use `@` in the input box for workspace files.
- After the gateway restarts, the first request may fail once and then recover by itself.
- Old notifications posted before the upgrade no longer respond when tapped.
- On the first upgrade after a fresh install, only the current version's notes are shown.
- In split screen, while you're looking at the chat, finished runs and pending prompts no longer send notifications.
- After a scheduled run, the background notification disappears within about a minute.
- Manually installing an older APK is no longer treated as an upgrade; you're told the files were changed and restored from the package.
- Installing an older toolkit from a local file or staged package asks you first.
- Skill packages with more than 4096 files are rejected.
