This release trims repeated work across the UI: the mobile bottom bar no longer wraps model, permission and usage onto multiple lines (tap usage on narrow screens for full values); splitter drags and terminal output are coalesced per frame, with covered terminals writing buffered output back in order when uncovered; settings, usage and lineage data are read on demand and polling stops off-page; file selection no longer rebuilds directory rows, and long PDFs locate pages by binary search.

## Chat

- **Bottom bar in one row**: model, permission mode and usage stats no longer wrap to multiple lines. Long provider / project names ellipsize first, with further degradation on narrow screens (short stats, hidden secondary text); 48px touch targets and the navigation safe area are preserved, and tapping stats shows the full values.
- **Layout work batched per frame**: tool-card follow scrolling and textarea measurement are coalesced, so a batch of tool results no longer re-measures one by one.

## Split view and terminal

- **Drag applies once per frame**: split width is saved only when the drag ends, not on every move.
- **Covered terminals buffer output**: when another pane covers the terminal, output is buffered (64 KB cap; overflow goes straight to the terminal) and written back in order when uncovered or on tab switch — no data loss, no focus stealing. Replay still marks truncation only when the gap exceeds the ring buffer.

## Settings, usage and lineage

- **Read on demand**: settings categories and usage stats load only when their page needs them, and polling stops when you leave; usage polling schedules the next tick only after the current response, avoiding request pile-ups.
- **Lineage map loads later**: the ~60 KB map script is deferred until the lineage page is first opened, with retry on failure; background refreshes keep your drag position.

## Files and previews

- **Selection keeps directory rows**: in a 1,000-file list, selecting preserves the original rows, thumbnails and keyboard focus; async operations only update the view that started them, and closing an unchanged preview no longer re-lists the directory.
- **Long PDFs use binary search**: jumping to page 1,100 of a 1,200-page document takes about a dozen page-location reads instead of over a thousand; switching or closing releases old reads and renders.

## Notes

- Full test suite passes (1,800+ gateway tests plus Java stub tests).
- Upgrading does not touch existing sessions, settings, or archives.
