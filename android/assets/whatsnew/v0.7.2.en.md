This release fixes seven issues: input focus, the lock-screen permission, the new-conversation sidebar, background sessions mixing into the list, components lost on toolchain reinstall, path-alias uninstall, and getting stuck at "Waiting for gateway" on some devices.

## Input focus

- Beyond the pane close/hide case, focus stolen from the main WebView is handled too: focus is returned to the main WebView before the touch is dispatched, and the input method is forced to reconnect on release. Tapping an input no longer gives "no response, occasionally a keyboard but no cursor".

## Lock-screen verification

- Adds the biometric permission declaration: on some devices the consent dialog could never appear, so toggles like "privileged commands without confirmation" and "keep-alive boost" reset to off after every restart. The dialog now works and settings persist.
- When the dialog can't appear, the message now distinguishes "missing permission" from other failures instead of one vague line.

## New conversations and background sessions

- The sidebar refreshes as soon as a new conversation's file lands on disk, without waiting for the turn to finish.
- Background daemon sessions no longer mix into the recent list.

## Toolchain reinstall

- After reinstalling or switching the toolchain, stale component records no longer block installs or uninstalls; components whose files are gone now show as "damaged" rather than "installed"; when the old toolchain marker can't be read, it is treated as the same version — no more silent "says installed, files actually gone" corruption.

## Path-alias uninstall

- openai-bridge and similar components no longer reject uninstall with "not a managed bridge install" when switching between the /data/data and /data/user/0 spellings — directories are identified by device and inode, not by string comparison.

## Waiting for gateway (some devices)

- On some devices (e.g. certain Android 17 models) 127.0.0.2 is unreachable, so the app could never verify the gateway and the UI stayed at "Waiting for gateway" forever. The app now probes this address at startup and automatically falls back to 127.0.0.1 when it fails; devices where the probe succeeds behave exactly as before.
- Note: on such devices the UI and the built-in browser share 127.0.0.1. If you use the built-in browser to visit another service on 127.0.0.1 yourself, the session cookie goes along. This exists only on those devices and only when you open such an address yourself.

## Notes

- All seven fixes have regression tests; upgrading does not touch existing sessions, settings or archives.
- Thanks to the users who reported, reproduced and independently reviewed these issues.
