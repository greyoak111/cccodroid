This release fixes several security issues, plus a problem that could freeze the app.

## Switches to turn on again after updating

- "Privileged commands without per-command confirmation", "Enhanced background keep-alive", "Device tools" and the screen-reading mode are all off after the update. Turn them on again in Settings.
- When you turn one on, the system screen-lock prompt appears. Verify, and it stays on after cccodroid restarts; skip it, and it only lasts until the app restarts. This keeps other programs from changing these settings.
- On devices without a screen lock, or below Android 11, these only last until the app restarts.

## Security

- Fixed several security issues.
- After Shizuku is activated, cccodroid turns wireless debugging back off if it turned it on for activation, and stops the adb server it used. The first launch after updating cleans up anything left behind by earlier versions.
- Device tools ask once per session before the first screen read, tap, typing or screenshot.
- In the file panel, committing, discarding, pulling or pushing in a Git repository whose own config would run commands now lists those commands and waits for your confirmation.
- If a project (or a folder above it) contains settings that run automatically when opened, such as hooks or MCP servers, you're asked before the first message. Choose "Don't load" and the turn goes ahead without them; allow, and it's remembered until those settings change. Scheduled tasks never load settings you haven't confirmed.
- UI and gateway files are checked against the app package on every launch and restored if they've been modified.
- The adb server started from the terminal now uses a socket in the app's private folder instead of 127.0.0.1:5037. If you really need 5037, add `-P 5037` to the command.
- "Network" in HTML preview applies only to the page you allowed; another page needs its own permission.
- Turning on web debugging with `~/.webdebug` from the terminal now asks for confirmation the first time.

## Appearance

- The light "Construct" look now has a paper-tone slider under Settings → Appearance: left is whiter, right is yellower; the default is unchanged. The status bar follows it. Thanks to chenshi723 for the suggestion.

## Viewer

- Tapping "Open as text" on a binary file such as an APK put the whole file into the editor as text, which froze the app until it was force-stopped. Now:
  - APKs, archives, libraries, fonts, and audio/video files no longer offer "Open as text";
  - for files it can't tell by name, the viewer checks the start of the file first and shows a note instead of opening the editor if it's binary. UTF-16 text with a BOM still opens normally.
