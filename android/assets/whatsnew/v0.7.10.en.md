This release keeps queued messages from being lost on storage errors: they are only cleared when the session is confirmed deleted; when the store is unreadable they are held with a notice, and sent normally after it recovers. Scheduled tasks closed or deleted while queued no longer come back to life, and a user stop no longer triggers automatic retries. Session-list category cache survives refreshes, making long lists faster.

## Queued messages

- **Storage errors no longer drop messages**: when the session directory is temporarily unreadable (storage failure), queued messages are no longer treated as "session deleted" and discarded — they are held with a notice in the queue, and sent normally after the store recovers. Messages of sessions confirmed deleted are still cleaned up as before.

## Scheduled tasks

- **Tasks closed while queued don't come back**: a task paused or deleted after being queued but before starting is not revived by re-enabling; a user stop no longer triggers automatic retries. Explicit approval, manual runs, and ordinary-failure retries keep their existing behavior.

## Session list

- **Category cache survives refreshes**: refreshing the session list no longer evicts the previous round's category cache; the next round keeps the latest 5,000 entries, making categorization and reordering of long lists faster. Content edits still invalidate the cache; totals, pinned, and guardian-session filtering are unchanged.

## Notes

- Full test suite passes (nearly 1,800 gateway tests plus Java stub tests).
- Upgrading does not touch existing sessions, settings, or archives.
