This release fixes the issue where some devices got stuck on "Waiting for gateway…" at launch with v0.7.16, and adds diagnostic logging around it.

## Startup fix

- **Cookie writes now run on the main thread**: when the gateway boot id changes, writing the WebView session cookie is dispatched to the main Looper; background threads (ui-prove, the WebView IO thread) no longer throw because CookieManager.setCookie requires a Looper.
- **Exception isolation**: a failed cookie write can no longer spoil the already-verified gateway identity proof, so the UI no longer reloads repeatedly within tens of milliseconds and then stays stuck on "Waiting for gateway…" after using up its reload budget.
- **Diagnostics**: non-200 responses and request failures for static assets now log a redacted path, making similar issues easier to locate.

## Notes

- Full test suite passes (1950 gateway tests plus Java stub tests).
- Upgrading does not touch existing sessions, settings, or archives.
