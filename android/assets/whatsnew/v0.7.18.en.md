This release fixes the Extensions-page GitHub CLI login getting stuck on "Requesting a one-time code from GitHub…", along with a dead Android watchdog heartbeat and a redundant confirmation dialog during login.

## GitHub login

- **One-time code detection**: when gh copies the code to the clipboard it prints "One-time code (XXXX-XXXX) copied to clipboard", while the old regex only matched "one-time code: XXXX-XXXX", so the UI waited at "Requesting a one-time code…" forever. Both formats are now recognized, with ANSI color codes stripped.
- **No more clipboard confirmation dialog**: the login subprocess PATH no longer includes app/pre (termux-clipboard-set / xdg-open); lightweight xdg-open / termux-open-url shims that only record the URL are placed first, so gh no longer tries to write the clipboard in the background and trigger an "Allow writing to clipboard?" prompt.

## Stability

- **Install heartbeat restored**: Android SELinux prevents the app from reading /proc/uptime, so the watchdog heartbeat fell back to wall-clock time, which the Java side rejected as a future timestamp and kept the installer grace period from ever applying. It now falls back to os.uptime() (same base as SystemClock.elapsedRealtime) before wall-clock time.
- **Terminal bridge hardening**: cli-bridge now has a socket timeout, a response size cap, a 200k-character stdin cap and an idle timeout, and supports the `--` separator, avoiding hangs and oversized input.
- This release also includes the v0.7.17 startup fix (some devices stuck on "Waiting for gateway…").

## Notes

- Full test suite passes (gateway and Java stub tests).
- Upgrading does not touch existing sessions, settings, or archives.
