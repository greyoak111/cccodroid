This release adds **direct editing** for MCP servers and fixes a silent token-loss bug in the remote MCP form ([#225](https://github.com/greyoak111/cccodroid/pull/225)). Both come from community contributor wumingzhinu's report and implementation; the edit feature also absorbed ideas from their independent implementation ([#226](https://github.com/greyoak111/cccodroid/pull/226)).

## Edit MCP servers directly

- User-level entries (including disabled ones): tap **Edit**, or **long-press / double-click** the entry to open the editor — name, transport (stdio / http / sse), and command or URL are all editable. No more delete-and-re-add.
- Tokens are never echoed: existing headers and env vars show **names only**. Leave blank = keep the value; type a new one to replace it (same key wins); tap the × on a chip to delete it from the config.
- Saving does a "remove + rewrite" behind the scenes; if the rewrite fails, the old config is **restored as-is**, and if even the restore fails you're told plainly. Renaming onto an existing name (including names in the disabled list) is rejected outright.
- Editing a disabled entry only updates the disabled list; enabling it adds the new config back.

## Remote MCP token-loss fix

- Writing `Authorization=Bearer …` with an equals sign in the add form used to silently become an environment variable — remote MCP servers have no child process, so the token was never sent, ending in a far-from-the-truth `Dynamic Client Registration rejected (HTTP 404)`. The input hint now switches to `Header: value` for http / sse, submits with `KEY=value` are blocked with the correct syntax shown, and the backend enforces it too ([#225](https://github.com/greyoak111/cccodroid/pull/225)).
- List entries show configured **header names** (never values), so you can tell at a glance whether the token is actually set.
- **Behavior change**: switching the transport to stdio while editing drops headers (Claude doesn't store headers for stdio servers) — a confirmation lists which headers will be lost before saving.

- Upgrading does not touch existing sessions, settings, or archives.
